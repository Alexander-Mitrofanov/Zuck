Help

      
Which input should I use?
Use raw FASTA or four-line FASTQ reads for a full run. Gzip compression is supported. Upload one single-end file or two paired files with corresponding read identifiers and order. Individual reads may be at most 20,000 bases long.
Retained cycles are Zuck’s cycles.txt output: one cycle sequence per line. Cycle replay skips graph construction and does not provide read-based confidence or linkage evidence.

      
Service limits
16 GiB total upload, 32 GiB expanded input, 64 GiB working storage, 8 GiB of result files, and 4 hours per analysis.

      
What does the example show?
The example is a small synthetic cycle dataset with a shared repeat and distinct spacers. Its precomputed results were generated by the same Zuck executable as this release. “Use example input” runs that dataset through the service.

      
What is in the download?
Machine-readable groups and entries, text reports, confidence evidence, a run manifest, and retained cycles when generated. Read-supported group and edge tables are included when the input supplies that evidence. The preview displays primary groups.

      
How are jobs and data handled?
No account is required. Job access uses a private recovery link; save it before leaving the page. Results are compressed and retained for 3 days after completion. Uploaded reads and temporary files are removed after processing. Incomplete uploads expire after 4 hours without activity. If a worker restarts during analysis, the job reports a failure so that you can submit it again.

    
Zuck builds a compact de Bruijn graph, discovers bounded cycles, and reconstructs repeat and spacer sequences. The default two-sided method preserves observed repeat–spacer pairing. Discovery is heuristic and is not exhaustive. Length filters constrain reported groups; they do not expand discovery.
